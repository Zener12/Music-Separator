# Music Source Separation — нейросеть: полный саммари

## Задача

Разделить миксованный музыкальный трек на 4 источника: **vocals, drums, bass, other**.
Метрика качества — SDR (Signal-to-Distortion Ratio, дБ).

Датасет: MUSDB18 (100 train + 50 test треков, стерео WAV, 44100 Hz).

---

## Архитектура модели (`model.py`)

### Общая идея: Multiplicative Masking

Модель не предсказывает спектрограмму источника напрямую. Вместо этого:
1. Вход — спектрограмма **микса**
2. Выход — 4 маски [0, 1], по одной на источник
3. Маска умножается на микс → предсказание источника: `source = mask × mix`

Почему маски, а не прямое предсказание?
Маска физически ограничена [0, 1]: источник не может быть громче микса.
Прямое предсказание ничем не ограничено → нестабильнее в начале обучения.

### U-Net: encoder-decoder со skip connections

```
Вход (batch, 1, 1025, 130)
    ↓ EncoderBlock 1 → (batch, 16, 512, 65)   + skip_1
    ↓ EncoderBlock 2 → (batch, 32, 256, 32)   + skip_2
    ↓ EncoderBlock 3 → (batch, 64, 128, 16)   + skip_3
    ↓ Bottleneck     → (batch, 64, 128, 16)
    ↑ DecoderBlock 3 ← skip_3 → (batch, 32, 256, 32)
    ↑ DecoderBlock 2 ← skip_2 → (batch, 16, 512, 65)
    ↑ DecoderBlock 1 ← skip_1 → (batch, 16, 1025, 130)
    ↓ Conv 1×1       → (batch, 4, 1025, 130)
    ↓ Sigmoid        → маски [0, 1]
```

Зачем skip connections?
Encoder сжимает информацию и теряет локальные детали (конкретные частоты и моменты).
Skip connections передают эти детали напрямую в decoder, минуя сжатое представление.

### Блоки

**ConvBlock**: `Conv2d → BatchNorm2d → LeakyReLU(0.2)`
- `bias=False` в Conv2d — BatchNorm всё равно содержит свои смещения (beta), отдельный bias лишний
- LeakyReLU вместо ReLU: при x < 0 ReLU даёт градиент = 0 (нейрон "умирает"). LeakyReLU даёт 0.2×x → нейроны живут

**EncoderBlock**: `ConvBlock (stride=1)` → сохранить как skip → `ConvBlock (stride=2)` → downsampling
- stride=2 вместо MaxPool: параметрический downsampling, обучается вместе с сетью

**DecoderBlock**: `ConvTranspose2d (stride=2)` → upsampling → concat со skip → `ConvBlock`
- После upsampling размеры могут не совпасть со skip на 1 пиксель (нечётные размеры) → `x[:, :, :skip.shape[2], :skip.shape[3]]` для выравнивания

### Количество каналов

Выбрано минимальным под 4 GB VRAM: 1→16→32→64.
Для 8+ GB можно пробовать 32→64→128.

## Предобработка (`preprocessing.py`)

### Почему не сырой сигнал?

22050 чисел в секунду. Нота длится ~50мс — в сыром сигнале её не видно.
Спектрограмма показывает частоты в каждый момент времени.

### Почему STFT, а не мел-спектрограмма?

Из мел-спектрограммы нельзя точно восстановить аудио — частотные бины нелинейно смешаны.
STFT обратим: `magnitude × exp(i×phase)` → `librosa.istft` → аудио.

### Параметры

- `SAMPLE_RATE = 22050` — вдвое меньше оригинала (44100), покрывает до 11025 Hz (теорема Найквиста). Вдвое меньше данных → вдвое быстрее обучение
- `N_FFT = 2048` → `freq_bins = 1025`, разрешение ~10 Hz
- `HOP_LENGTH = 512 = N_FFT // 4` — шаг между окнами STFT

### `log_magnitude`

`np.log(magnitude + eps)` — логарифм сжимает динамический диапазон (от тихого до громкого).
`eps = 1e-7` защищает от `log(0) = -inf`.

### `normalize` / `denormalize`

Z-score нормализация: `(x - mean) / std`.
Зачем не MinMax? MinMax зависит от конкретного трека. Z-score нормализует относительно среднего и разброса — работает для треков любой громкости.

Mean и std сохраняются рядом с кэшем (`track_000_stats.npy`) — нужны для обратного преобразования в `evaluate.py` и `nmf_baseline.py`.

### `segment_spectrogram`

Нарезает спектрограмму на сегменты по `SEGMENT_FRAMES = ceil(3.0 × 22050 / 512) = 130` фреймов.
Последний неполный сегмент отбрасывается (не дополняется нулями — маска на нулевом участке дала бы артефакты).

### `prepare_tensor`

`torch.FloatTensor(magnitude_segment.copy()).unsqueeze(0)` → shape `(1, freq, frames)`.
`.copy()` обязателен: `np.load(mmap_mode='r')` возвращает read-only массив, PyTorch не может создать тензор из read-only памяти.

## DataLoader (`data_loader.py`)

### Структура датасета

```
train (100 треков):
  0–79   → обучение нейросети
  80–99  → валидация нейросети
test (50 треков) → финальная оценка
```

`MUSDBDataset` принимает `track_start` и `track_end` для нарезки подмножества.

### Кэширование спектрограмм

**Проблема:** `__getitem__` вызывается тысячи раз за эпоху. STFT — дорогая операция.
**Решение:** вычислить спектрограммы один раз в `__init__`, сохранить в `./cache/`.

Файлы: `track_000_mix.npy`, `track_000_vocals.npy`, `track_000_stats.npy`, ...

Нормализация источников: источники нормализуются теми же mean и std что и микс.
Почему? Маска = предсказание / микс. Если масштабы разные — маска теряет смысл.

### `mmap_mode='r'`

`np.load(path, mmap_mode='r')` — memory-mapped чтение. С диска читается только нужный срез, не весь файл (~10 MB ради 0.5 MB).

**Побочный эффект:** массив read-only → `.copy()` перед конвертацией в тензор.

### DataLoader параметры

- `batch_size=8` — увеличено с 4 (экономит на overhead, VRAM позволяет)
- `num_workers=0` — на Windows > 0 вызывает deadlock в multiprocessing
- `pin_memory=True` — держит батчи в page-locked памяти CPU, ускоряет передачу на GPU
- `shuffle=True` только для train — чтобы модель не запоминала порядок треков

## Обучение (`train.py`)

### Loss-функция

`0.9 × L1 + 0.1 × SDR`

**L1 (MAE):** устойчива к выбросам, стабильна в начале обучения.
**SDR Loss:** `(-10 × log10(||target||² / ||target - pred||²)).mean()` — оптимизирует целевую метрику напрямую.

Почему не только SDR?
В начале обучения pred ≈ random → `||target - pred||²` огромный → log уходит в -inf. SDR нестабилен пока L1 "раскачивает" модель.

`keepdim=True` в `torch.sum` — чтобы не потерять батч-измерение при делении и считать SDR для каждого источника отдельно.

### Оптимайзер и scheduler

**Adam** вместо SGD: адаптирует lr для каждого параметра. Быстрее сходится на разреженных градиентах (как спектрограммы).

**ReduceLROnPlateau**: если val_loss не улучшается `patience=5` эпох → lr × 0.5.
Финальный lr после 50 эпох: `7.81e-06` (начальный `1e-3`, делился примерно 7 раз).

### Gradient Clipping

`clip_grad_norm_(model.parameters(), 1.0)` — обрезает норму градиента до 1.0.
Без него при больших градиентах веса улетают в NaN.

### Зачем `optimizer.zero_grad()`?

PyTorch по умолчанию накапливает градиенты. Без обнуления каждый шаг суммирует градиенты всех предыдущих шагов.

### Checkpoint

Сохраняется только когда `val_loss < best_val_loss` — лучший по валидации.
Содержит: `epoch`, `val_loss`, `model_state_dict`, `optimizer_state_dict`.

Зачем optimizer state? Adam хранит "моменты" для каждого параметра. Без них первые итерации после загрузки нестабильны.

Автовозобновление: при запуске находит последний `.pt` файл и продолжает с `epoch + 1`.

### Результаты обучения (50 эпох)

```
Epoch 50: Train: 0.4183 | Val: 0.1328 | LR: 7.81e-06
```

Train >> Val — не overfitting. Объяснение:
1. BatchNorm в train-режиме использует статистику текущего батча (нестабильнее)
2. Val-треки (80–99) объективно проще по содержанию
3. SDR-компонент во время train прыгает на сложных случаях

## Оценка (`evaluate.py`)

### `separate_track`

Разделяет произвольный аудиосигнал:
1. STFT → magnitude + phase (phase сохраняется для iSTFT)
2. log + normalize → нормализованный лог-спектр
3. Нарезка на сегменты по 130 фреймов
4. Каждый сегмент через модель → маски → предсказания
5. Склейка сегментов → денормализация → exp → iSTFT с фазой микса

**Phase approximation:** фаза источников берётся от микса, не предсказывается — стандартная практика для маскинг-методов.

**Важный нюанс:** phase нужно обрезать до длины склеенного спектра (последний неполный сегмент отброшен).

### `compute_sdr`

Использует `mir_eval.separation.bss_eval_sources`.
Длины ref и est выравниваются через `min(len(ref), len(est))` — после iSTFT длина может чуть отличаться.

### Финальные результаты (50 тестовых треков)

```
vocals    : 2.72 dB
drums     : 3.36 dB
bass      : 0.29 dB
other     : 0.09 dB
average   : 1.62 dB
```

Для сравнения — Demucs v3 (SOTA):
```
vocals    : 8.99 dB
drums     : 8.72 dB
bass      : 7.84 dB
other     : 5.09 dB
average   : 7.66 dB
```

Разрыв ~6 dB объясняется: Demucs обучался на MUSDB18-HQ + 800 дополнительных треков, архитектура на порядок сложнее (гибридный waveform+spectrogram трансформер).

## Хронология проблем и решений

### 1. RAM error при загрузке датасета

**Проблема:** musdb грузит треки на 44100 Hz, полный трек весит ~400 MB. При предобработке в `__getitem__` на каждый вызов — 5 чтений + 5 ресэмплингов + 5 STFT.

**Решение:** дисковый кэш. STFT считается один раз в `__init__`, сохраняется как `.npy`. `__getitem__` только читает нужный срез.

### 2. Скорость: 120 батчей за час

**Проблема:** STFT пересчитывался на каждый вызов `__getitem__`.

**Решение:** кэш + `mmap_mode='r'` + `float32` + `pin_memory=True` + `batch_size 4→8`.

**Результат: ~175x ускорение** (120 батч/час → 700 батч/2 мин).

### 3. `torch.compile` на Windows

**Проблема:** требует Triton, который не поддерживается на Windows.

**Решение:** удалён.

### 4. UserWarning: non-writable tensor

**Проблема:** `mmap_mode='r'` возвращает read-only массив → PyTorch не может создать тензор.

**Решение:** `.copy()` в `__getitem__` и `prepare_tensor`.

### 5. RuntimeError: stack equal size

**Проблема:** количество сегментов вычислялось из метаданных, которые не совпадали с реальным shape кэшированного файла.

**Решение:** если кэш существует — читать `shape[1]` из реального файла. В else-ветке: `n_segments = mix_norm.shape[1] // SEGMENT_FRAMES`.

### 6. Data leakage: test использовался как val

**Проблема:** изначально `get_dataloaders` не возвращал отдельный val — test-сет использовался и для валидации, и для оценки.

**Решение:** разбивка train 80/20 через `track_start`/`track_end`. Добавлен отдельный `val_loader`.

### 7. Ресэмплинг в evaluate.py

**Проблема:** `separate_track` и `compute_sdr` получали аудио на 44100 Hz. Модель обучалась на 22050 Hz → разные частотные диапазоны → SDR ~ -3 dB.

**Решение:** `librosa.resample(audio, orig_sr=track.rate, target_sr=SAMPLE_RATE)` перед подачей в модель и для эталонов.

**Эффект:** average SDR вырос с -3.11 dB до +1.62 dB.

### 8. Модель на CPU при инференсе

**Проблема:** `load_checkpoint` загружал модель но не перемещал её на device. Тензор на CUDA, веса на CPU → RuntimeError.

**Решение:** `model.to(device)` в конце `load_checkpoint`.
